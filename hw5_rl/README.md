# ДЗ5: RL для вызова инструментов

Итог: [EXPERIMENTS.md](EXPERIMENTS.md), [PDF](report.pdf), [метрики всех вариантов](runs/run_02/comparison.csv). Baseline + три RL-конфигурации выполнены; максимальный BFCL overall в этом запуске - **0.7173** (strict).

Краткий результат — [EDA.md](EDA.md). Скрипт работает на CPU, использует только ToolACE и токенизатор, не скачивает веса и не запускает обучение. BFCL не участвует в выборе примеров или разбиении.

## Повторение

Из корня репозитория, Python 3.10+ (фактический локальный запуск: 3.14.6):

```bash
python3 -m venv hw5_rl/.venv
hw5_rl/.venv/bin/pip install -r hw5_rl/requirements-eda.txt
HF_HOME=hw5_rl/data/hf hw5_rl/.venv/bin/python hw5_rl/eda.py \
  --data hw5_rl/data/toolace.json \
  --out hw5_rl/eda_outputs \
  --bfcl hw5_rl/materials/bfcl.jsonl
hw5_rl/.venv/bin/python hw5_rl/check_eda.py hw5_rl/eda_outputs
```

Если исходника нет, скрипт скачивает его по фиксированной ревизии. SHA256 проверяется всегда. Токенизатор также закреплён ревизией; свой локальный снимок можно передать через `--tokenizer`. Пакеты EDA закреплены отдельно от GPU-окружения задания.

Повторный запуск с другим `--out` и затем `check_eda.py FIRST --compare SECOND` проверяет совпадение всех шести выходных файлов по SHA256. Выполненное сравнение сохранено в `verification.json`. Смена версии Python или библиотек меняет запись окружения в `stats.json`, даже если данные совпали.

Опция `check_eda.py --check-token-lengths` дополнительно читает готовые JSONL и проверяет длины всех итоговых prompts официальным токенизатором. Эта проверка также выполнена. При экспорте сохраняется порядок полей схем и исторических аргументов, использованный при токенизации; каноническая сортировка применяется только для хешей.

## Файлы

- `eda.py`: разбор, аудит, длины, разбиение и экспорт; `check_eda.py`: случаи с нестандартными именами/литералами, учёт исключений и отсутствие пересечений диалогов/prompts.
- `eda_outputs/stats.json`: все агрегаты; `exceptions.jsonl`: 500 неподдерживаемых схем и 6 осторожно отложенных эталонов; `split_manifest.json`: разделение всех исходных диалогов.
- `eda_outputs/candidates.jsonl`: все 11 946 структурно подготовленных решений, включая длинные/повторные; `train.jsonl`, `validation.jsonl`: итоговые prompts, tools, структурные эталоны, индексы источника и длины. Объёмные экспорты исключены из Git, но доступны локально и полностью восстанавливаются скриптом.
- `provenance.json`: ревизии и хеши источников/официальных файлов токенизатора. `materials/`: неизменённые Dockerfile, evaluate.py, bfcl.jsonl из материалов задания; их код не запускался. Исходный ToolACE в Git не добавляется.

В экспорт попадают только решения после user. Для no-call сохранён структурный эталон, а не требование повторить текст ответа. Для исторических вызовов сохраняются структурированные аргументы и исходные имена, включая пробелы и `/`; функции не переименовываются. Поля `target_tokens` измеряют исходный эталон после сериализации chat template, но не обещают такую длину будущей генерации.

Разбиение: объединить дубликаты диалогов и точные prompts; для каждой группы взять минимальный SHA256 диалога; validation, если `int(SHA256(JSON(["42", group_hash])),16) % 10 == 0`, иначе train. Дубликаты prompts удаляются после разбиения. Порог длины фиксирован: prompt ≤ 3072, эталон ≤ 1024. BFCL читается только после формирования train/validation.

## Доступ к GPU

Подключение к учебному серверу подтверждено; использована одна A100-SXM4-80GB и образ `rlvr-homework:latest`. Версии совпали с заданием (vLLM имеет суффикс сборки `+cu129`). Инструкции доступа и приватные полные веса находятся в локальном LOCAL_ARTIFACTS.md; для воспроизведения на другом сервере достаточно материалов Dockerfile и configs.

Утверждённые награды, команды и статус выполнения - в [RUNBOOK.md](RUNBOOK.md). Старые домашние задания не менялись; коммитов, push и отправки в Stepik не было.
