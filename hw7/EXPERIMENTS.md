# ДЗ 7. Квантизация и дистилляция Qwen3

Я разбирал русские запросы к голосовому ассистенту. По каждому запросу модель возвращала intent и пары «тип слота, значение». Лучший ученик получил Q = 0,593. Это 102,5% Q учителя. Среди шести квантизированных моделей лучший результат дал AWQ W4A16 на MASSIVE с Q около 0,39.

## Как я измерял качество

Я использовал MASSIVE ru-RU. Из 2 033 примеров validation я выбрал 256 после перемешивания с seed 42. Порядок примеров, инструкция, 60 классов intent и 54 типа слотов были одинаковыми для всех моделей. Я отключил режим рассуждения. Модели генерировали ответы жадно с пределом 128 новых токенов. Размер батча равнялся 16.

Q — среднее Intent Accuracy и Slot Micro F1. Для F1 я сравнивал мультимножества пар по всей выборке. При ошибке JSON или схемы я засчитывал ошибку intent и пустой список предсказанных слотов. Frame EM требует полного совпадения intent и слотов. Valid JSON Rate учитывает и синтаксис JSON, и допустимые имена классов. Ответы моделей я оценивал без исправлений.

## Квантизация

Я начал каждый прогон с одной ревизии Qwen3-8B. Для калибровки взял 64 непустых текста из train. Лимит на текст составил 256 токенов. В AWQ и GPTQ W4A16 я использовал симметричные 4-битные веса с группой 128. Выходной слой lm_head оставил в BF16. В SmoothQuant установил smoothing_strength = 0,5 и применил GPTQ W8A8 по рецепту семинара.

При замене MASSIVE на WikiText значение Q у GPTQ оказалось выше примерно на 9,5 п. п. Остальные настройки совпадали. После токенизации и обрезки средняя длина текста составила 12,9 токена для MASSIVE и 90,8 для WikiText. Корпуса различались и языком, и длиной текстов.

Больше всего помог переход с GPTQ на AWQ. Я взял те же 64 запроса MASSIVE, размер весов остался 6,1 ГБ, а Q выросла с 0,23 до 0,39. Со SmoothQuant я получил Q 0,37, но веса заняли уже 9,4 ГБ. Поэтому для сдачи я выбрал AWQ.

Оставлять один блок в BF16 тоже не помогло. С первым блоком в BF16 я потерял около трёх пунктов Q, с последним — около двух. Оба чекпоинта при этом стали больше.

Я сложил размеры файлов safetensors. Токенизатор в размер весов не входит. Для оценки качества я загрузил каждый сохранённый чекпоинт. Измерение показывает сжатие на диске. Скорость выполнения INT4-ядер я не измерял.

## Дистилляция

Я получил жадные ответы Qwen3-32B на 384 запросах из train. Учил Qwen3-8B предсказывать токены ответа учителя, включая EOS, когда учитель его сгенерировал. Токены инструкции, запроса и паддинга исключил из функции потерь. Эталонную разметку train не использовал как цель обучения.

Я обучил два отдельных адаптера LoRA для q_proj и v_proj. В обоих опытах ранг равнялся 16, alpha — 32. Обучение заняло две эпохи по 48 шагов оптимизатора. На один шаг приходилось 8 примеров. Я менял только learning rate. Лучший результат на dev дал Qwen3-8B + LoRA · LR 3e-4. Этот адаптер я сохранил в student_sft. В предварительном запуске с learning rate 1e-4 я получил Q = 0,578, при повторе — 0,581. Файл обучающих ответов учителя совпал побайтно. Для выбора адаптера я сравнивал два варианта итогового запуска.

Учитель получил Q = 0,578, порог 90% равен 0,521. Ученик превысил порог на 7,2 п. п. Прирост Q относительно исходной Qwen3-8B составил 31,5 п. п. Число ответов, прошедших проверку схемы, выросло со 131 до 249 из 256. В 112 ответах baseline после завершённого JSON стояла лишняя закрывающая скобка. Оба варианта ученика я сравнил на той же dev-выборке, по которой выбрал адаптер.
